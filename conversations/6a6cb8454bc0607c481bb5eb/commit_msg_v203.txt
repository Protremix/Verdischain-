WALLET v2.0.3: Fix Send/Receive (were non-functional) + fake portfolio data

CRITICAL - Send/Receive were completely non-functional:
- Home screen Send/Receive quick-action buttons opened a fake placeholder
  bottom sheet ("Initiating Send VRDX transaction..." + Dismiss button)
  instead of navigating to the real SendPage/ReceivePage, which already
  existed fully built (address validation, QR scan, fee estimate, share)
  but were never wired up. Fixed: buttons now push the real /send and
  /receive routes.
- Even after reaching the real Send page, transfers were signed from a
  hardcoded FAKE address (verdis1q83f7k9...) that nobody controls, using a
  hardcoded FAKE balance (1250.75 VRDX). Fixed: both now read the actual
  active wallet address/balance (home_providers.selectedAddressProvider /
  balanceProvider), the same source of truth used everywhere else in the
  app.
- The signing key (mnemonic) was never loaded into TransactionRepositoryImpl,
  so every real send attempt would throw "Wallet locked - mnemonic not
  available for signing". Fixed: transactionRepositoryProvider now loads
  the mnemonic from secure storage via onboardingWalletProvider and calls
  repo.setMnemonic() before any send, matching the non-custodial design
  that was already documented in the repository's own code comments but
  never implemented.
- Removed a hardcoded fake block number (#1284525) shown on every
  successful send - the UI already handled a null blockNumber gracefully,
  so it now just doesn't show a number we don't actually have yet.
- Removed a fragile optimistic local balance-subtraction hack after send;
  balance now refreshes from the real chain via provider invalidation.

FIXED - Portfolio Allocation Breakdown showed fake data:
- The 'Tap for breakdown' bottom sheet on the balance card showed a
  hardcoded fake 15,400.00 VRDX staked (55.3%) and a fake $3,850 total
  portfolio value, regardless of the wallet's real balance or stake
  (reported by Rojs: screenshot showed 0.00 VRDX balance but breakdown
  claimed 15,400 staked). Fixed: breakdown now uses the real
  StakingSummaryData.totalStaked and computes live percentages/USD value.
- Found and fixed a decimals bug in the same file: balance was divided by
  10 decimals (10,000,000,000) but Verdis Chain uses 9 decimals per
  system_properties (tokenDecimals=9). This would have silently shown any
  future nonzero balance at 1/10th its real value. Now uses
  NetworkConfig.decimals consistently.

No visual/design changes - only wiring real data into the exact same UI.

Files: portfolio_view.dart, transactions_providers.dart, balance_card.dart
