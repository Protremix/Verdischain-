1. Executive Summary

Overview

The Verdis blockchain is a fully operational Layer-1 chain implementing Delegated Proof of Stake (DPoS) consensus, a stack-based smart contract virtual machine, an automated market maker (AMM) decentralized exchange, and integrated eco-tracking features (carbon credits, reforestation logging, green validator scoring).

This audit covers the production deployment at verdischain.com, including the Node.js backend (10,220 lines of compiled TypeScript), 134 REST API endpoints, Ethereum-compatible JSON-RPC layer, Nginx reverse proxy with TLS 1.3, and systemd-managed service with auto-monitoring.

All 13 security checks are active and passing. The system demonstrates a solid security foundation with real cryptographic operations (secp256k1 ECDSA, SHA-256, Keccak256), comprehensive rate limiting, replay protection, and admin authentication. Findings below outline areas for improvement before the scheduled September 2026 external audit.

9. Findings

VD-001
CORS Wildcard on Public API
Medium
Description
The Nginx configuration sets Access-Control-Allow-Origin: * on all endpoints, including the JSON-RPC interface. While acceptable for a public blockchain node, sensitive admin endpoints should restrict origins to trusted domains.
Impact
Any website can make cross-origin requests to the API. Admin endpoints are protected by API key, but the wildcard CORS increases exposure surface for browser-based attacks.
Recommendation
Restrict CORS on /api/security/* and admin paths to https://verdischain.com only. Keep wildcard for public read endpoints and JSON-RPC.
VD-002
Admin API Key Stored in Plaintext Source
High
Description
The admin API key is hardcoded in the server source code (server.js and deployment scripts). The key is a 64-character hex string with 256 bits of entropy, but its exposure in source files means anyone with code access has admin privileges.
Impact
Source code access (GitHub, server backup, deploy scripts) grants full admin capabilities including token minting, contract deployment, and block production.
Recommendation
Move the admin API key to an environment variable (VERDIS_ADMIN_KEY) or a secrets manager. Rotate the current key. Remove all hardcoded instances from source files, deploy scripts, and Python utilities.
VD-003
No Swap Memory on Server
Low
Description
The server has 3.7 GB RAM with 0B swap. Under high mempool load or large state serialization (6.5 MB JSON), an OOM kill could crash the blockchain node without graceful recovery.
Impact
Potential service interruption under memory pressure. systemd will restart the service, but unsaved state (up to 30s of blocks) could be lost.
Recommendation
Add 2 GB swap file (fallocate -l 2G /swapfile && mkswap /swapfile && swapon /swapfile). Reduce autosave interval from 30s to 15s to minimize state loss window.
VD-004
Contract State Serialization Not EVM-Compatible
Info
Description
Smart contract state is stored as JavaScript Map objects serialized to JSON. While functional, this differs from EVM-style Merkle Patricia Trie storage, limiting cross-chain interoperability and state proof verification.
Impact
Light clients cannot verify contract state without trusting the full node. No state proofs available for bridge integrations.
Recommendation
For Mainnet V1, document this as a known limitation. For V2, consider implementing Merkle Patricia Trie for contract state to enable SPV proofs and trustless bridges.
VD-005
DEX Pool ECOGR/VRS Has Zero Liquidity
Low
Description
The ECOGR/VRS DEX pool exists but has 0/0 reserves. Any swap attempt against this pool will fail or return 0 output. The pool is visible in the UI and API, which could confuse users.
Impact
Poor user experience for DEX traders. Potential for front-end confusion. No financial risk since the pool returns 0 for any input.
Recommendation
Either seed the ECOGR/VRS pool with initial liquidity, or remove it from the active pools list and mark as "pending launch" in the UI.
VD-006
Validator Stake Display Inconsistency
Info
Description
The /api/validators endpoint returns 5 validators with stake=0, while the blockchain info reports 27 registered validators. The stake display does not reflect the 4B VRDX balances held by validator wallets.
Impact
Explorer and dashboard show zero stakes, which looks unprofessional. No consensus impact — block production is functioning correctly.
Recommendation
Map validator wallet balances to their stake display. Show all 27 registered validators in the API with proper stake amounts and green scores.
VD-007
Carbon Credits and Reforestation Records Empty
Info
Description
The state file shows 0 carbon credits and 0 reforestation projects. The eco-tracking infrastructure is deployed and functional (endpoints respond correctly), but no eco-activities have been logged yet.
Impact
The "First Fully Green Blockchain" claim has no on-chain evidence yet. This should be seeded before public marketing.
Recommendation
Mint initial carbon credits and log reforestation projects to demonstrate the eco-tracking system is live. Verify the green validator scoring algorithm produces non-zero scores.
VD-008
No TLS Certificate Auto-Renewal Verification
Low
Description
The Let's Encrypt certificate for verdischain.com expires October 29, 2026 (88 days remaining). While certbot is installed, no cron job or systemd timer for auto-renewal was verified during this audit.
Impact
If the certificate expires, the site and API become inaccessible via HTTPS. Wallet and DEX functionality would break for all users.
Recommendation
Verify certbot's renewal timer is active (systemctl status certbot.timer). Add a monitoring check for certificate expiry (< 30 days = alert).

11. Priority Recommendations

Before September 2026 External Audit

1. Rotate and externalize the admin API key (VD-002). Move to environment variable, remove all hardcoded instances, and rotate the current key. This is the highest-priority finding.

2. Restrict CORS on admin endpoints (VD-001). Add Nginx location blocks for /api/security/* that only allow verdischain.com origin.

3. Add swap and reduce autosave interval (VD-003). 2 GB swap file + 15s autosave for crash resilience.

4. Seed eco-tracking data (VD-007). Mint carbon credits and log reforestation projects to substantiate the green blockchain claim.

5. Fix validator display (VD-006). Map wallet balances to stake amounts and show all 27 validators with green scores.

6. Verify TLS auto-renewal (VD-008). Confirm certbot timer is active and add expiry monitoring.

7. Clean up empty DEX pool (VD-005). Either seed ECOGR/VRS with liquidity or remove from active list.

For Mainnet V1 (August 2026)

Document the contract state storage model (VD-004) as a known V1 limitation with a V2 roadmap for Merkle Patricia Trie. Ensure all findings VD-001 through VD-008 are resolved or acknowledged before the external audit.
