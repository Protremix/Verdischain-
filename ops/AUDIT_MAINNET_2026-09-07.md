## FINDINGS

### ✅ CRITICAL-0 (УСТРАНЕНО СЕГОДНЯ): Публичный сайт работал на ТЕСТНЕТЕ

**Самая серьёзная находка аудита.** Обнаружена при проверке зависимостей веба.

**Было:**
```
https://rpc.verdischain.com   → genesis 0xf72f1241…  = ТЕСТНЕТ
https://verdischain.com/rpc   → genesis 0xf72f1241…  = ТЕСТНЕТ
wss (через /ws)               → 127.0.0.1:9944 → :9933 = ТЕСТНЕТ
```

Nginx на `91.98.160.145`: `upstream substrate_rpc → 127.0.0.1:9950` (тестнет), а `location /rpc` вообще шёл в обход upstream — `proxy_pass http://127.0.0.1:9950` напрямую. `ws_filter_proxy.py` имел жёстко прописанный `BACKEND_PORT = 9933`.

В веб-бандлах **386 вхождений** `https://verdischain.com/rpc` и 88 вхождений `https://rpc.verdischain.com` — explorer, wallet, dex, faucet читали тестнет: цепь с отставанием финализации 72 000+ блоков и публично известными dev-ключами Alice…Ferdie.

Мейннет при этом не имел публичного эндпоинта вообще.

**Смягчающее обстоятельство:** аккаунтов на тестнете 16, на мейннете 33 — реальных пользователей не было, чужие деньги не пострадали.

**Как исправлено:**
1. Поднята **отдельная full-node мейннета** `verdis-public-rpc` на `185.84.224.91:9955` — **без `--validator`, keystore пустой (0 файлов)**, `--rpc-methods=safe`, `roles=["Full"]`. Она физически не может подписывать блоки, голосовать или вызвать equivocation, поэтому не влияет на баланс 15/21.
2. Обнаружена и обойдена ловушка: `/data/verdis-chain/chain-specs/mainnet-raw.json` — **разный файл на разных хостах**. На HostKey лежал spec с genesis `0x60488cb4…`. Взял проверенный с Contabo (sha256 `aca92919e13da10f`, идентичен `mainnet-raw-v13.json`), сверил хеш, установил как `mainnet-raw-v13-verified.json`.
3. Туннель `verdis-mainnet-tunnel` с веб-хоста на `185.84.224.91:9955`, ключ ограничен `restrict,port-forwarding,permitopen="127.0.0.1:9955"` — новых портов в интернет не открыто.
4. Переключены `upstream substrate_rpc`, `location /rpc` и `ws_filter_proxy` (через `VERDIS_WS_BACKEND_PORT=9960`).

**Проверено:**
```
https://rpc.verdischain.com   → MAINNET  best=47971
https://verdischain.com/rpc   → MAINNET  best=47972
wss через /ws                 → 0x2284393d…  MAINNET
публичная нода: active, roles=["Full"], keystore файлов 0
author_insertKey / author_rotateKeys / system_addReservedPeer → "RPC call is unsafe to be called externally"
12/12 доменов → 200
15 валидаторов не тронуты, lag=3, equivocation 0
9955 снаружи закрыт
```

Все изменения обратимы: бэкапы `upstreams.conf`, `verdischain-com.conf`, `ws_filter_proxy.py` с таймстампами, старая строка оставлена закомментированной.

### 🚨 CRITICAL-1: Нулевой запас авторитетов

**Измерено:**
```
authority set          21
порог финализации      15
ключей у нас           15
работает валидаторов   15
ЗАПАС                  0
```

6 авторитетов из сета не имеют приватного ключа **ни на одном** сервере. Их публичные ключи:
```
0xc684b6445815fe73b22b70e6...
0x2d78d9baa868f09e1167a6ec...
0x866979f9f431a08fed738db3...
0x1d1b56d9c8ffd65ac29154c9...
0x89bd2c69f05d4e83041262dd...
0xab97b020d2cab53fbde3c794...
```

**Последствие:** падение **любого** одного валидатора → 14 из 15 → **финализация мейннета останавливается**. Ровно так встал тестнет 2 сентября и стоял 5 суток.

**Почему нельзя просто исправить:** Sudo в рантайме нет. Уменьшить сет до 15 (порог стал бы 11, запас 4) можно только через голосование Council/Democracy. Ключи для 6 слотов восстановить невозможно — сгенерированы air-gapped как raw keypairs, сиды уничтожены в 3 прохода.

**Варианты:**
1. **Governance-предложение** уменьшить authority set 21 → 15. Порог станет 11, появится запас 4. Требует Council-голосования
2. Найти 6 ключей, если они на USB, о котором ты упоминал
3. Оставить как есть и жить с риском

Это **главный блокер аудита Halborn** — не отсутствие 6 ключей само по себе, а сеть, которая останавливается от падения одной ноды.


fail2ban сразу забанил 8 IP (1 на Online.net, 7 на Contabo) — перебор шёл в реальном времени.

**Подводный камень:** файл назвал `99-verdis-hardening.conf`, но `50-cloud-init.conf` шёл раньше, а в sshd **первое** вхождение параметра выигрывает — настройка не применялась. Переименовал в `00-verdis-hardening.conf`, после чего `sshd -T` подтвердил `no`. Каждое изменение проверено `sshd -t` до reload; вход по ключу подтверждён после.

Также ограничен размер журнала (`SystemMaxUse=500M`, `SystemKeepFree=2G`) — ранее он был не ограничен, а ENOSPC уже убивал ноды тестнета.
